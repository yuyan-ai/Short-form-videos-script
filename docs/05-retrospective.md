# 项目复盘

实际投入时间为 3 小时。我主要负责框架设计、整体思路和个人验证使用，AI 辅助了代码实现、测试和文档整理。

## 学习收获

做完这个项目，我对短视频脚本的设计有了更多理解：除了写出文案，还要考虑分镜、时长、素材依据和规则约束。把业务需求与 AI 结合，做成可以实际使用和验证的流程，让我很有满足感。

## 项目中的主要难点

从实现和运行记录看，主要难点是让文案创作与事实检查兼顾。最初的严格白名单容易检查，但限制了主题和风格表达；后来允许原创叙事，增加额外模型审核，同时保留引用和时长的确定性检查。

模型审核也可能漏判。真实复验中，文案审核通过后，确定性规则仍发现无关引用并阻止完成。模型随后改稿，但最终因审核错误和时间预算耗尽而未交付。这说明仅靠模型说“通过”还不够，检查结果必须和当前稿件对应。

以上难点归纳来自项目代码和执行记录，不代表所有修复均由我独立完成。

## 下一步

- 改进原创文案审核，减少漏判与重复调用。
- 用实际录音校准时长估算。
- 继续拆分 runtime.py，便于维护决策与执行逻辑。
